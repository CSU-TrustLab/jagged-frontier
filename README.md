# Agent Robustness Evaluation of Code Agents — Artifact

It has three parts: one that **runs** the robustness experiments, one that **analyzes** the agent
trajectories those experiments produce, and one that **visualizes** the
aggregate results.

---
## [Dashboard/](Dashboard/)

A single self-contained HTML page,
[dashboard.html](Dashboard/dashboard.html), for exploring the pooled
results of the experiments above. All run data is embedded in the file as a JSON
payload. You need to open the html in a browser, no server or build step required. The current
build covers 16 experiments (4 models × 2 benchmarks × 2 scaffolds), 54
instances, and ~17k sample runs, with 20 independent runs per instance per
condition.

The left sidebar filters everything on the page by model, benchmark, scaffold,
individual experiment, or instance id. Six tabs sit above the view:

- **Guide** — landing page: counts for the current filter, and a
  glossary of the metrics (stability degradation, SPTs, baseline/mutant,
  Newcombe CI, bootstrap CI).
- **Overview** — baseline vs mutant resolve rates, stability degradation per
  experiment, and effort inflation (all runs and resolved-only), each with an
  optional 95% bootstrap CI toggle.
- **Heatmap** — per-instance colour grid, with columns groupable by model,
  scaffold, and/or benchmark; per-instance Newcombe CIs are shown.
- **Per-Instance** — sortable table of every instance; clicking a row opens a
  breakdown of steps, cost, and per-sample outcomes.
- **SPT Insights** — metrics regarding different SPT combination and impact.
- **Radar / Web** — multi-metric spider chart comparing experiment profiles
  across chosen axes and grouping dimensions.

Every chart and table exports via the PNG / SVG / CSV buttons in its card
header, and the whole page prints to PDF. Charts are drawn with Chart.js loaded
from a CDN, so the first load needs network access.

## [agentic_robustness_experiment/](agentic_robustness_experiment/)

Measures how robust coding agents are to **semantic-preserving transformations
(SPTs)** — rewrites of a repository's source that cannot change its behaviour.
For each SWE-bench / SWE-Bench-Pro task it extracts the seed source, generates N
mutants, runs the agent on each in a fresh container, and grades the result with
the standard harness. Every mutation is logged with file and line positions.

Bundled under `dependencies/`: the SPT library, the mini-swe-agent scaffold, and
the SWE-bench evaluator — so setup needs no external repository access.

Requires Linux, Docker, Python 3.10+, and an LLM endpoint (hosted or local).
Full setup and model configuration are in
[agentic_robustness_experiment/README.md](agentic_robustness_experiment/README.md).

## [trajectory-analysis/](trajectory-analysis/)

AI-assisted analysis of the trajectories generated by the experiments above. It
analyzes `*.traj.json` file generated by the agent and turns each `*.traj.json` into an evidence-grounded report: an
interactive offline `report.html` (issue description, phase graph, raw trajectory,
rule-based results) plus a machine-readable `analysis.json` with extracted phase
nodes, deterministic git/test/edit checks, issue keyword clues, and data
quality metadata. Batch runs also emit `index.html`, `summary.json`, and
`summary.csv`.


Details, input layout rules, credentials, and troubleshooting are in
[trajectory-analysis/README.md](trajectory-analysis/README.md).
